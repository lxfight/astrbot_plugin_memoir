# astrbot_plugin_memoir

模拟人脑记忆闭环（捕获 -> 巩固 -> 遗忘 -> 召回 -> 洞察）的 AstrBot 长期记忆插件。

不使用向量数据库 / RAG，检索为「精确 + 模糊」双通道：精确通道对整句短语、
tags/subject 等值命中大幅加分置顶；模糊通道基于 SQLite LIKE 子串匹配 +
相关性评分（命中线索数、tags 加权、强度、重要度），零额外依赖。
向量通道（sqlite-vec）为预留的实验扩展。

核心设计：**文本对话直接落库，长期记忆通过周期批量抽取生成**。
文本捕获不调用模型；支持的图片/语音在文本落库后由后台队列额外调用一次模型，转成可检索的文字描述。
结构化记忆带唯一索引 `memory_key`（`类别:主题` slug，由抽取模型生成），
去重范围包含会话、记忆类型与稳定人物 ID：同一个人的同类事实更新，不同人物与群公共事实分别保存。旧记忆保留历史身份标签，不根据同名昵称自动合并。

私聊与群聊的差异：

- 私聊：每轮「用户 + 助手」原文落库；抽取出的语义记忆（人物画像）衰减慢。
- 群聊：被动捕获每条消息原文落库（无采样门控），机器人自己的回复在响应后补记；召回时额外注入最近几条原文（补上群聊没有会话历史的短板）。
- 可选：群聊中经用户授权（`/memoir consent on` 自助开启，WebUI 可统一管理）的自我陈述，会以原文轮次形式桥接进其私聊记忆（默认关闭，带敏感度过滤）。

## 记忆闭环

- **捕获**：文本落库（raw_turns），值得长期记什么交给巩固阶段统一提炼。图片/语音保留占位符（`[图片]`/`[语音]`），所选模型支持时追加带 `[多媒体解析]` 标记的图片描述、图片文字及语音转写，参与检索和巩固。视频/普通文件目前保留类型占位符；媒体地址与二进制数据不写入记忆。群聊捕获支持忽略名单（发送者 ID）与关键词过滤，命中的消息不落库。
- **巩固**：后台周期扫描，达到数量阈值或静默超时的 scope 触发**一次**批量抽取。抽取前先用本批原文线索**召回相关旧记忆**（`consolidation_related_top_k`，替代全量注入，prompt 成本与记忆总量解耦），模型据此决策 update/insert/expire/ignore（含时间归一化与过期事实清理）+ 洞察 + 群聊自我陈述桥接；模型 insert 必须携带 `key`，群聊个人事实必须提供合法 `subject_id`（sender_id），公共事实填 null；按会话、人物、类型和 key 去重。洞察与认知一样参与 update/expire 与重复合并，避免过时洞察长期占据常驻层。相对时间在抽取时归一化为绝对日期（事件型事实以 `[YYYY-MM-DD]` 开头），过期事实由 LLM 顺带标记删除；tags 要求补充口语同义表达和上位词，作为跨措辞检索的桥梁。积压时最多连续消化 3 批；每次请求最多等待 60 秒；坏 JSON 或不合格结构重试一次，仍失败时进入隔离状态，不标记为抽取成功。可在 WebUI 查看原因并重试；明确的空 semantic_ops 才表示没有值得记忆的内容。巩固指令与对话数据分离注入（system/user），落库原文与生成的记忆文本折叠为单行并限长，收窄群聊提示注入的影响面。
- **召回**：三层注入，共享 `recall_max_chars` 字符预算（默认 6000，可配置 512–20000）；超长原文截断，仅强化实际进入提示词的记忆。
  - 常驻层：importance×strength 最高的语义记忆/洞察（稳定认知）；
  - 线索层：双通道检索（线索来自当前发言 + 最近上下文的中文 bigram/英文词）——精确通道（整句短语子串、tags/subject 等值命中）大幅加分置顶，模糊通道按相关性排序（结构化记忆 + 原文引用）；
  - 近因层：最近几条原文，仅群聊注入。
- **遗忘**：原文按 TTL（默认 14 天，0 表示不按时间删除）+ 单会话容量上限（500 条）清理——注意容量按「最近 500 条」保留，消息量大的会话实际可检索的原文窗口会明显短于 TTL；语义记忆/洞察按距上次激活（写入/更新/被召回）的自然日数做指数强度衰减，只影响排序不物理删除，事件型记忆（`[YYYY-MM-DD]` 前缀）的事件日过了 7 天宽限期后衰减锚点切换为事件日，过期时效事实无法靠召回强化常驻；超出单会话容量上限（200 条）时按召回优先级淘汰最弱者，重复认知由巩固抽取顺带合并。

## 多媒体消息

在插件配置中选择「后台小模型」，并在 AstrBot 对应提供商的「模型能力」中勾选其实际支持的「图像」和/或「音频」。后台模型留空时，使用消息所属会话的当前对话模型及其能力配置；能力未配置或仅支持文本时，保留占位符，不发送媒体给模型。

- 私聊用户消息与群聊被动捕获都支持纯图片、纯语音和图文/音频混合消息。同一条消息中可用且受支持的媒体合并为一次额外模型调用，会增加模型费用；解析不阻塞私聊回复钩子，也不会触发群聊回复。原文先落库，媒体完成后补充描述并保留原消息时间。
- 使用 AstrBot 消息组件解析网络地址、Base64 和本地文件路径。队列最多 32 条待处理/处理中任务，固定两个后台工作者。每条最多 4 个附件，每个解析后的文件不超过 10 MiB、合计不超过 20 MiB；输入引用（含 Base64）最多 4 MiB，超额时保留原文并记录失败。每个媒体解析最多等待 10 秒，模型描述最多等待 30 秒，整条任务最多 45 秒；单个附件损坏时继续处理其他附件，模型报错、超时或返回空内容时保留原文和占位符。
- 解析结果是模型生成的描述，不等同于用户原话。描述最多保留 800 字；有描述时，用户文本最多保留 1000 字，完整原始轮次仍受 2000 字上限约束。
- 群聊忽略名单、原文关键词、会话开关在媒体解析前生效；解析结果命中忽略关键词时删除对应原文和任务（此时媒体已送模型识别）；排队和处理中原文暂不参与巩固。
- 为支持重启恢复与失败重试，操作队列暂存媒体引用（包括本地路径、URL 或受限 Base64），这些引用不会进入记忆检索或模型召回。成功后立即清除引用，原文过期/删除后清理媒体任务；失败诊断最多保留 30 天。临时文件或链接失效时需要重新发送媒体。
- 仅处理启用后的新消息；旧占位符没有保存媒体源，无法补充识别。视频、普通文件及助手生成的媒体暂不解析。

## WebUI 管理页

插件在 WebUI 注册了「记忆管理」页面（插件详情页进入），SaaS 工作台式双栏布局：

- **概览**：会话 / 结构化记忆 / 原文 / 待巩固统计卡片
- **会话侧栏**：按私聊/群聊分组，搜索过滤，显示记忆数与待巩固状态
- **记忆与原文**：查看、搜索、删除；原文对话以聊天气泡时间线呈现（用户/助手分侧、群聊发言人头像配色、日期分组、「待巩固」呼吸提示），支持图片/语音占位符高亮
- **会话配置**：每个会话可独立覆盖策略（开关、召回条数、巩固阈值、静默时长、桥接开关与敏感度），未覆盖项自动继承全局；支持直接编辑全局默认配置（含后台模型选择）；桥接授权记录管理
- **体验**：粒子背景（随主题变色、响应鼠标、尊重系统减弱动效设置）、入场/切换动画、骨架屏加载、统一错误面板与重试
- **主题**：侧栏底部可选「跟随 / 浅色 / 深色」，选择保存在当前浏览器，刷新后保留并在同源标签页间同步。「跟随」优先使用 AstrBot 外观，未提供时跟随系统；手动选择不受宿主主题变化影响。浏览器禁止本地存储时仍可切换，但刷新后不保留。
- **小屏与可访问性**：窄屏标签栏、搜索框与配置表单自动换行，优化明暗文字对比度，主题选项支持键盘操作，触屏设备直接显示删除按钮。原文中的 `[多媒体解析]` 单独高亮，便于识别模型描述。
- **处理状态**：会话配置页显示媒体排队、处理中、失败数量及最早积压时长；支持刷新状态与重试。原文过期后禁止重试，重试受当前记忆开关约束。
- **来源**：记忆卡片可展开来源原文；模型未指定精确来源时显示该次巩固批次。原文被删除或过期会明确提示，不恢复已删除数据。
- **遗忘**：清空指定会话的全部记忆和关联处理任务；会话版本校验会丢弃正在处理的旧结果，防止清空后写回。

聊天侧只保留一个轻量指令 `/memoir`（显示当前会话记忆统计）。

## 会话级配置

会话覆盖存储于 `scope_configs` 表（增量字段，缺失即继承全局），对以下策略生效：

| 字段 | 说明 |
| --- | --- |
| `enabled` | 本会话记忆总开关（与全局类型开关叠加） |
| `recall_top_k` / `recall_core_top_k` / `recall_recent_turns` | 召回条数 |
| `recall_max_chars` | 召回总字符预算 |
| `consolidation_count_threshold` / `consolidation_idle_hours` | 巩固触发 |
| `bridge_enabled` / `bridge_max_sensitivity` | 群聊自我陈述桥接（叠加用户授权） |

关闭全局记忆或会话记忆会同时阻止捕获、巩固和桥接写入；桥接还检查目标私聊的开关。后台模型留空时，周期巩固使用捕获时保存的 AstrBot 会话标识选择该会话的当前模型。旧会话缺少标识时会记录失败，需选择后台模型或接收新消息后重试，以避免误用其他会话的模型。

全局配置另有 `consolidation_related_top_k`（巩固时注入的相关旧记忆条数，默认 20）。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/memoir` | 查看当前会话的记忆统计 |
| `/memoir consent on` / `off` | 用户自助开启/关闭群聊自我陈述桥接授权（不带参数查看当前状态；实际桥接还受全局与会话级桥接开关、敏感度上限约束） |

代码结构：

```
core/
  event_handler.py    钩子入口
  memory_recall.py    on_llm_request：常驻层 + 线索层 + 近因层召回与注入
  memory_writer.py    on_llm_response / 群消息：文本和媒体描述落库
  llm_helper.py       后台模型调用、按模型能力解析图片/语音
  media_processor.py  持久化媒体队列、并发控制与失败恢复
  consolidation.py    周期巩固任务：批量抽取 + 洞察 + 桥接 + 遗忘
  scope.py            私聊/群聊 scope 归属解析
  storage.py          aiosqlite 封装
  web_api.py          WebUI 后端接口
pages/
  memoir/index.html   WebUI 记忆管理页（bridge + iframe）
```

## 开发

```bash
uv sync
```

依赖变更后同步 AstrBot 加载所需的 requirements.txt：

```bash
uv add <package>
uv export --no-hashes --format requirements-txt > requirements.txt
```

WebUI 回归测试使用 Node.js 与 Playwright（需安装 Chromium），通过模拟插件 bridge 验证主题、布局及配置保存，不连接真实记忆服务：

```bash
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node --test tests/test_webui.cjs
```
